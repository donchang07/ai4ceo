## 1. AI 프로젝트 라이프사이클

### 1.1 6단계 프로세스

```
1. 문제 정의        → 어떤 비즈니스 문제를 해결할 것인가?
       ↓
2. 데이터 수집/탐색  → 필요한 데이터가 있는가? 충분한가?
       ↓
3. PoC 개발        → 기술적으로 가능한가? 효과가 있는가?
       ↓
4. 파일럿 운영      → 실제 환경에서 작동하는가?
       ↓
5. 확산/스케일업    → 전사/전체 서비스로 확장할 수 있는가?
       ↓
6. 운영/개선        → 지속적으로 성능을 유지하고 개선하는가?
```

### 1.2 단계별 핵심 의사결정

| 단계 | 핵심 질문 | Go/No-Go 기준 |
|:-----|:---------|:-------------|
| 문제 정의 | 비즈니스 가치가 있는가? | ROI 예상 > 15%, 전략적 중요도 |
| 데이터 탐색 | 데이터가 충분한가? | 최소 학습 데이터량 충족 |
| PoC | 기술적 가능성 입증 | 목표 정확도 70% 이상 |
| 파일럿 | 현업 수용성 확인 | 사용자 만족도 70% 이상 |
| 확산 | 확장 가능성 확인 | 비용 효율성 및 안정성 |
| 운영 | 성능 유지 | KPI 달성 지속 여부 |

## 2. AI 팀 구성

### 2.1 AI 팀의 핵심 역할

| 역할 | 주요 업무 | 필요 역량 |
|:-----|:---------|:---------|
| **AI PM** | 프로젝트 기획, 이해관계자 조율 | 비즈니스 이해 + AI 기초 |
| **데이터 사이언티스트** | 모델 설계, 학습, 평가 | 머신러닝, 통계, Python |
| **ML 엔지니어** | 모델 배포, 최적화, 운영 | MLOps, 클라우드, DevOps |
| **데이터 엔지니어** | 데이터 수집, 파이프라인 구축 | ETL, SQL, 빅데이터 기술 |
| **데이터 분석가** | 데이터 탐색, 인사이트 도출 | 통계, 시각화, SQL |
| **현업 전문가** | 도메인 지식 제공, 레이블링 | 해당 업무 전문 지식 |

> 💡 **소규모 팀 구성 팁**: 초기에는 AI PM + 데이터 사이언티스트 + 현업 전문가 3인으로도 PoC 가능

### 2.2 AI 팀 조직 모델

**중앙집중형 (CoE, Center of Excellence)**
- 별도 AI 전담 조직이 전사 프로젝트 지원
- 장점: 기술 역량 집중, 노하우 공유
- 단점: 현업과의 거리감, 병목 발생 가능

**분산형 (Embedded)**
- 각 사업부에 AI 인력 배치
- 장점: 현업 이해도 높음, 빠른 실행
- 단점: 기술 수준 편차, 중복 투자

**하이브리드 (Hub & Spoke)** ← 권장
- AI CoE(허브)가 표준/플랫폼 제공 + 사업부(스포크)에 현업 AI 인력 배치
- 대부분의 선진 기업이 채택하는 모델

## 3. AI 프로젝트 성공과 실패

### 3.1 AI 프로젝트 성공 조건

1. **명확한 비즈니스 목표**: "AI를 위한 AI"가 아닌 실제 비즈니스 문제 해결
2. **충분한 양질의 데이터**: 데이터 없이는 AI 없음
3. **경영진의 지속적 지원**: 장기 투자와 변화관리 필요
4. **현업의 적극 참여**: AI는 기술팀만의 프로젝트가 아님
5. **애자일(Agile) 방식**: 빠른 실험, 빠른 학습, 빠른 개선
6. **올바른 성공 지표**: 기술 지표(정확도)보다 비즈니스 KPI 중심

### 3.2 AI 프로젝트 실패 원인 Top 5

1. **문제 정의 실패** (30%): "어떤 AI를 만들까"가 아니라 "무슨 문제를 해결할까"로 시작해야 함
2. **데이터 부재/품질 불량** (25%): 훈련 데이터 부족, 레이블 오류, 편향 데이터
3. **기술-현업 간 단절** (20%): 개발한 AI를 현업이 사용하지 않음
4. **스케일업 실패** (15%): PoC는 성공했지만 실제 운영 환경에서 성능 저하
5. **변화관리 부재** (10%): AI 도입에 대한 직원 저항, 프로세스 미정비

## 4. MLOps: AI 운영 관리

### 4.1 MLOps란?

**MLOps (Machine Learning Operations)**:
DevOps 개념을 ML/AI에 적용한 것. 모델 개발부터 배포, 모니터링, 재학습까지 자동화하는 체계.

```
코드 관리 → 데이터 관리 → 모델 학습 → 모델 검증 → 배포 → 모니터링 → 재학습
                                                               ↑______________|
                                                             (자동화 파이프라인)
```

### 4.2 CEO가 알아야 할 MLOps 핵심

- **모델 드리프트**: 시간이 지나면 AI 성능이 떨어짐 → 정기적 재학습 필요
- **A/B 테스트**: 새 모델을 일부 사용자에게만 적용하여 검증 후 전체 배포
- **모델 버전 관리**: 문제 발생 시 이전 버전으로 빠른 롤백 가능
